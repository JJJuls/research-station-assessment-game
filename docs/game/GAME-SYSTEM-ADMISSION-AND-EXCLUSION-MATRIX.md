# Game-System Admission and Exclusion Matrix (Q01-Q33 blueprint)

Documentation only; base `bfca741`. Admission rule: a system is admitted
only when its purpose, Q mapping or non-scored classification,
contamination safeguards, and implementation dependency are explicit.
Classes: `MANDATORY_RESEARCH` (MR), `MANDATORY_PLAYABLE_FOUNDATION` (MPF),
`OPTIONAL_POST_PILOT` (OPP), `CONTROL_OR_USABILITY` (CU),
`ENGAGEMENT_ONLY_UNSCORED` (EU), `EXCLUDED` (EX).

Source-requirement codes: SPEC = tier-2 measurement specification; V3 =
build contract; ES = event-schema.md; SP = scoring-plan.md; AUTH =
authority/open-decisions doc; PILOT = pilot scenario reports.

## 2. Explicitly excluded (unless separately approved by the research owner)

| Feature                                                    | Class      | Why excluded                                                                                | Excluded alternative considered                                                                           |
| ---------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Literal fishing (rods, bait/fish tables, angling minigame) | EX         | No canonical requirement; pure reference-game import; time cost against a fixed budget      | "Sample dredging" reskin — still untraceable; rejected                                                    |
| Farming/crops                                              | EX         | No requirement; long-horizon sim mechanics contradict session scale                         | Greenhouse-tending side task — no Q mapping beyond what Side Repair covers; rejected                      |
| Combat / weapons                                           | EX         | Contradicts identity; V3 forbids; dexterity confound                                        | "Pest zapping" minigame — rejected                                                                        |
| Conventional currency                                      | EX         | V3 forbids money/economy; introduces reward-optimisation confound across all tasks          | Points/credits displays — rejected (any global-number display risks a good-player score read)             |
| Shops / trading economy                                    | EX         | As above                                                                                    | Requisition kiosk with prices — rejected; item registry is need-based                                     |
| Crafting system                                            | EX         | No requirement; fetch-and-fit steps cover the research-relevant behaviour without recipes   | Recipe-based repair — rejected (puzzle-skill confound)                                                    |
| Romance / relationship meters                              | EX         | Explicitly banned; NPC approval must never be scored                                        | Friendship levels with Kai — rejected                                                                     |
| Social-simulation schedules                                | EX         | No requirement; time-of-day sim inflates scope                                              | NPC day cycles — rejected                                                                                 |
| Large open-world exploration                               | EX         | Controlled room-based world is a validity requirement (standardised opportunities)          | Exterior station surface area — post-pilot expansion only with owner approval                             |
| Unrelated collectables                                     | EX         | Untraceable engagement filler; completionism confound for OPT                               | Lore datapads as collectables — rejected for pilot (EU candidate post-pilot, unscored, if owner approves) |
| Procedural filler quests                                   | EX         | Untraceable; breaks standardisation                                                         | Randomised side tasks — rejected                                                                          |
| Item rarity tiers                                          | EX         | No research or gameplay rationale                                                           | Rare component drops — rejected                                                                           |
| XP / skill levels / stat boosts / power upgrades           | EX         | V3 forbids; would change task difficulty across participants                                | Badges that alter abilities — rejected (non-power status labels remain allowed)                           |
| Environmental/biological sample collection                 | EX (pilot) | No canonical task requires it; would be gathering without a mapping                         | Reconsider post-pilot only with an explicit research-owner mapping                                        |
| Free item drop / world littering                           | EX         | Untraceable state, cleanup-signal contamination (Q04 must come from designed opportunities) | Drops constrained to bins/slots (admitted above)                                                          |
