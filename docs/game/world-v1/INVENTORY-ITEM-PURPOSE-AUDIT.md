Astra 2026-09-08. This is a replacement experience design, not a claim that the earlier proposed itemPurpose.ts registry exists. Current engine/store/telemetry and M02/M03 isolation remain unchanged.

| Stage          | What appears and why                                                                                                   | Teaching / disposition                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |

| Utility/Core   | No new collectible requirement; tools visually returned/archived after their last authorised use                       | Do not mutate the inventory engine merely to show closure. Core readiness uses current fixed non-scored feeds                          |

## Presentation and isolation contract

The I overlay separates tools, station materials and documents through display metadata, without changing slot conservation, stack rules, storage, input semantics or telemetry. Do not add sorting as a measured task. The field strip is hidden when empty or irrelevant, as the current InventoryHud already does; the selected-name cue is brief. A tool's display explains source, use and destination. Store interactions outside authorised windows remain contextual and are never reused as primary signals.

All transfer/consume/discard permissions remain exactly those of the current engine. This design does not authorise the older audit's proposed new no-discard/no-transfer restrictions. A pure itemPurpose.ts display registry may explain existing state; it cannot rewrite it. Fable must demonstrate mouse and keyboard transfer parity and M02/M03 namespace isolation before accepting the visual change.
